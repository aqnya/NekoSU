# Source layout

The Dart source is split by responsibility. Dependencies point inward:

```text
app -> features -> shared / data / core
data -> core
shared -> data / core
```

## Layers

- `main.dart`: process entry point. Loads persisted settings and starts the app.
- `app/`: composition root, application shell, navigation chrome and theme.
- `features/`: user-facing screens grouped by product area (`home`, `install`,
  `apps`, `modules`, `settings`, `about`, `diagnostics`).
- `data/`: models and repositories for apps, modules and kernel features.
- `core/`: platform bridges, FFI and cross-cutting controllers/services.
- `shared/`: reusable widgets and layout primitives shared by features.
- `l10n/`: ARB catalogs; `app_localizations.dart` is generated by Flutter.

Rules:

- `core/` and `data/` must not import `features/`.
- `shared/` must not import `features/`.
- A feature may depend on `core/`, `data/` and `shared/`.
- Cross-feature navigation is wired in `app/` whenever possible; direct feature
  imports should be limited to nested screens owned by that feature.
